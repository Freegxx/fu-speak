---

## 1. 产品概述

### 1.1 产品名称

**fu-speak**

### 1.2 产品定位

面向英语学习者的通用版学习应用，核心能力为：

1. **背单词**（词书 + 间隔复习）
2. **练口语**（日常场景 AI 对话 + 纠错）

两者相互独立，不强制绑定。

### 1.3 目标形态

- 用户端：可打包为**微信小程序**与 **App**（同一套客户端方案）
- 网页端 / 管理端：运营与内容管理
- 后端：统一 API 与账号体系

---

## 2. 技术架构（方向）

| 层级 | 方案 | 说明 |
|------|------|------|
| 后端 + 管理网页 | **若依（RuoYi）Vue3** | 用户、词书、学习数据、运营配置等 |
| 用户端（小程序 / App） | **uni-app（Vue）** | 学习者主入口，调用后端接口 |
| 前端 / 后端 / 网页 | 均需具备 | App 纳入整体方案 |

> 说明：用户端以 uni-app 通打小程序与 App；若依负责后端接口与管理后台网页。

---

## 3. 信息架构（用户端）

用户端**只做三个板块**，保持简单：

| 板块 | 作用 |
|------|------|
| **单词** | 词书学习、复习、熟练度标记 |
| **口语** | 日常对话 AI 练习与纠错 |
| **我的** | 账号、等级、学时、词汇量测试、月度学习图 |

## 4. 功能需求：单词

### 4.1 词书

- 单词来源于**词书**，非无散词堆。
- 首批词书类型包括（可扩展）：
  - 大学英语**四级**
  - 大学英语**六级**
  - **英语二**（考研英语二等）
  - 其他同类考试 / 场景词书（后续扩展）

### 4.2 每日学习量

- 每日学习单词数量由**用户自行设定**（例如 100）。
- 当日实际学习队列凑满该数量，来源为：
  1. **尚未进入学习池**的新词
  2. **到期需要复习**的词  
- 规则倾向：复习词优先占名额，剩余名额再引入新词进入学习池；总数等于用户设定值。

### 4.3 复习策略（艾宾浩斯）

- 每个单词的再次出现时间依据 **艾宾浩斯遗忘曲线（间隔复习）** 安排。
- 具体间隔天数与当次**熟练度评分**联动（见 4.5）。

### 4.4 单词学习页交互

#### 4.4.1 出示方式（中英交替）

- **有时先展示中文**：用户可输入英文单词，验证是否正确。
- **有时先展示英文**：用户可输入中文释义，验证是否正确。
- **输入可选**：也可不输入，直接点击页面其他区域展开释义等信息，再标记熟练度。

#### 4.4.2 展开内容

点击页面其他区域后，可展示包括但不限于：

- 释义
- 读音相关信息
- 对应例句
- 其他相关单词

#### 4.4.3 发音

- 提供发音入口，点击后朗读当前单词。
- 支持 **英式发音** 与 **美式发音** 切换或选择。

#### 4.4.4 进入下一词

- 用户**标记熟练度之后**，自动跳转到下一词。

### 4.5 熟练度（1–10）

#### 4.5.1 控件形态

- 页面底部为 **1–10 横向滑动 / 点选条**：
  - 最左为 **1**，最右为 **10**
  - 颜色由 **黄 → 深绿** 渐变
  - 横条在垂直方向上**适当加高**，便于点击

#### 4.5.2 关键刻度说明

| 分数 | 含义与行为 |
|------|------------|
| **7（熟悉）** | 视为「熟悉」。**当日不再出现**该词；之后按记忆曲线在若干天后再进入复习。横条在 **7 下方**展示对应说明文案（当日不再出现，几天后按记忆曲线再出现）。 |
| **9（及 10）** | 视为**完全记忆**。该词**不再进入复习队列**，表示学习完成。横条在 **9 下方**展示文案：完全记忆，不再出现复习队列。 |
| **低于 7** | 不满足「今日不再出现」；当日仍可能再次抽到。间隔复习仍结合评分与艾宾浩斯规则计算。 |

> 注：历史想法中的「陌生 / 模糊 / 熟悉 / 熟练」四按钮方案，已被 **1–10 横条**替代；其中「熟悉」明确对应 **7**。

## 5. 功能需求：口语

### 5.1 定位

- 口语模块与单词模块**解耦**，不要求围绕当前背词进行。
- 练习内容仅从**日常对话场景**产生。

### 5.2 AI 对话

- 调用 **AI** 进行口语对话练习。
- AI 协助**纠正**用户表达（如用词、语法、更自然的说法等；具体纠错粒度实现阶段再定）。

### 5.3 对话记录

- 系统**记录对话内容**，支持用户回看历史对话（展示形态实现阶段再定）。

---

## 6. 功能需求：我的

### 6.1 基础信息

- 用户登录信息
- 用户等级
- **累计学习小时**

### 6.2 词汇量测试

- 提供**词汇量测试**能力（题型与算法实现阶段再定）。

### 6.3 月度学习图（打卡风格）

- 以「月」为维度展示每日学习情况。
- 某天发生学习行为后上色，规则如下：

| 当日学习时长 | 颜色 |
|--------------|------|
| **10 分钟以下** | **黄色** |
| **10 分钟及以上** | **浅绿色** |
| **30 分钟及以上** | **深绿色** |

> 设计意图：类似打卡日历，用颜色深浅反映学习投入。

## 7. 管理端（若依）首期范围建议

首期管理后台建议优先覆盖：

1. 词书与单词内容管理（导入四级 / 六级 / 英语二等；音标、释义、例句、相关词等字段）
2. 用户与学习进度相关数据查看
3. 与口语对话记录相关的基础管理（若需要运营侧查看）

非首期重点：复杂运营活动、社交排行、重度游戏化等（可后续迭代）。

## 8. 非功能与约束（当前约定）

- **先完善需求与想法，再开始写业务代码**（本文档即该阶段产物）。
- 产品结构保持简单：用户端三个 Tab 为主。
- 多端进度应最终跟随账号同步（小程序 / App / 网页登录用户数据一致），具体同步策略实现阶段细化。
